# Squash rebrand plan

## Goal and decisions

- Replace project-owned references to the previous brand with `Squash` in all casing, including first-party UI, package/code identifiers, paths, docs, and committed generated codec artifacts.
- Set the canonical site origin to the supplied `https://squash.techie-jim.net`.
- Preserve precise attribution links to the upstream repository and third-party/vendor references. Do not rewrite Git history or repository metadata, dependencies, or disposable local output (`node_modules`, `.tmp`, ignored `build/`). Rebuild output from renamed sources during validation.

## Implementation steps

1. Update visible product branding and metadata in README, issue template, UI copy, app/PWA metadata, analytics title, and the logo SVG. Rename asset filenames and update references where needed.
2. Rename the root npm package and synchronize `package-lock.json`; replace project-owned mentions in docs, scripts, and existing planning files, including plan filenames when they carry the old project name. Keep precise upstream attribution links intact.
3. Rename first-party codec identifiers end to end: Rust package names and lockfile entries, wasm-pack package metadata and generated JS/type/WASM filenames, TypeScript imports, service-worker imports, and build/container labels. Set MozJPEG build metadata to the replacement name.
4. Regenerate checked-in Rust/WASM codec package outputs with their existing build scripts so generated names and runtime asset references match the renamed packages. Avoid hand-editing compiled artifacts.
5. Use only the supplied `https://squash.techie-jim.net` origin; do not invent or substitute destinations for existing upstream GitHub URLs.

## Validation

- Run `npm run build` to verify updated imports, generated codec artifacts, and the production bundle. Run applicable codec build scripts for renamed Rust/WASM packages as needed before the application build.
- Scan tracked text and filenames case-insensitively for remaining old-name references. Remaining matches should be limited to verified upstream attribution or third-party/vendor material. Confirm the old site origin is absent from owned source and the supplied new origin is present.
- Inspect generated output and `git diff --check`; confirm ignored local output and repository metadata were not added to the change.
