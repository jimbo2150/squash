# Feature development

Features are organized by role under [`src/features/`](../src/features/). Most directories separate code by execution context: `shared/` contains types and metadata used on both sides, `client/` contains browser/UI code, and `worker/` contains code exposed through the shared worker. A feature only needs the layers it uses.

For the existing encoder export contract and a description of feature folders, see [`src/features/README.md`](../src/features/README.md). This guide focuses on where behavior is registered and what to update when adding or changing features.

## Where to make a change

| Change | Main source locations | Additional wiring to check |
| --- | --- | --- |
| Encoder format, defaults, output MIME type or extension | [`src/features/encoders/`](../src/features/encoders/), especially the format's `shared/meta.ts` | Client option controls; worker adapter or browser encoder; native codec artifacts and cache list if applicable |
| Encoder options UI | The format's `client/` directory under `src/features/encoders/` | `shared/meta.ts` option type and defaults; [`src/client/lazy-app/Compress/Options/index.tsx`](../src/client/lazy-app/Compress/Options/index.tsx) renders the selected encoder's `Options` component |
| Decode an additional format | [`src/features/decoders/`](../src/features/decoders/) | Add MIME recognition as needed and dispatch in `decodeImage()` in [`Compress/index.tsx`](../src/client/lazy-app/Compress/index.tsx); check codec and offline-cache wiring |
| Processor implementation or options | [`src/features/processors/`](../src/features/processors/) | Add execution to `processImage()` and controls to [`Compress/Options/index.tsx`](../src/client/lazy-app/Compress/Options/index.tsx) |
| Shared preprocessing | [`src/features/preprocessors/`](../src/features/preprocessors/) | Add execution to `preprocessImage()` in [`Compress/index.tsx`](../src/client/lazy-app/Compress/index.tsx); current rotate control is in [`Compress/Output/index.tsx`](../src/client/lazy-app/Compress/Output/index.tsx) |
| Compare UI, output display, or result downloads | [`src/client/lazy-app/Compress/`](../src/client/lazy-app/Compress/) | Trace state and callbacks through `Compress/index.tsx`, `Options/`, `Output/`, and `Results/` |
| File selection or editor entry/exit | [`src/client/initial-app/App/index.tsx`](../src/client/initial-app/App/index.tsx) | Static entry point and share-target flow if affected |
| Offline install, precaching, or cache selection | [`src/sw/`](../src/sw/) | Explicit codec asset imports and feature tests in `to-cache.ts` |

## Automatic registration versus explicit wiring

`lib/feature-plugin.js` discovers:

- Every TypeScript file under `src/features/*/**/worker/*.ts` (excluding declaration files). It generates the worker API and client bridge metadata from each file's default export.
- Encoder, processor, and preprocessor `shared/meta.ts` files. It generates the encoder map and default processor/preprocessor state; encoder client exports are included with their metadata.

This does not create a complete feature by itself. The editor explicitly dispatches custom decoders, calls preprocessors and processors, and renders processor controls. When adding one of those capabilities, update the corresponding call site in the table above. Codec assets also are not automatically added to the explicit service-worker cache list.

Do not directly edit generated files: `src/features-worker/index.ts`, `src/client/lazy-app/worker-bridge/meta.ts`, and `src/client/lazy-app/feature-meta/index.ts` are generated by `lib/feature-plugin.js` during builds and are Git-ignored.

## Add or modify a feature

1. Find the closest neighboring implementation of the same role and execution model; browser-native encoders and WebAssembly-backed encoders have different adapters.
2. Add or edit only the required `shared/`, `client/`, and `worker/` layers. For a worker operation, use one uniquely named `.ts` file with a default export; the filename becomes the generated worker method name.
3. For an encoder, define its label, MIME type, extension, option type, and defaults in `shared/meta.ts`, then implement either a client encoder or a worker adapter and optional client `Options` UI. Follow the export contract in [`src/features/README.md`](../src/features/README.md).
4. For decoders, processors, and preprocessors, wire the new operation into the editor's explicit dispatch/execution path and add or update its controls where needed.
5. If WebAssembly assets or feature variants are involved, follow [Native codecs](native-codecs.md), including the service-worker cache review.
6. Run `npm run build`. There is no separate automated test script in the root `package.json`; manually verify the affected format and UI in the browser when possible.

Keep the feature's UI settings, shared option types/defaults, worker adapter, and codec option interface consistent. See [Architecture](architecture.md) for the complete runtime path.
